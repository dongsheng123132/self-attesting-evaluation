**本文件在第二轮任何一次回测之前写成并提交。** 第一轮的锚点是 `63d46b16fc99c421`（commit `a5e60eb`），
本轮另起一份预注册与另一次盖章——**v1 明写了「要加大网格需要一份新的预注册和一次新的盖章，
不能在那份结果上续写」**，这里执行它。

机器可读的一份是 [`prereg-v2.json`](prereg-v2.json)：

> `sha256 = 0354049996de1306f84e28dd3ad45412135f99b65faa827506c6967409601f57`

`backtest-v2.mjs` 启动时自校验此哈希，不符退出码 3 拒跑。

## 1. 为什么有第二轮：这是 v1 预先写好的处置，不是事后补救

第一轮 R1 不成立（`mean(F) = 0.303 < 0.5`）。v1 的 `prereg.json` 对这种情况**预先写了 else 分支**：

> 「网格或样本不足以产生可观的挖掘溢价；**须加大网格重跑，且在报告里如实写明设计被改过**。」

本轮即执行该条。**区别很要紧**：看到结果后临时想出的补救叫 p-hacking；跑之前就写好的处置叫预注册。
同一个动作，是哪一种只取决于它写在结果之前还是之后——而那一点，只有外部时间锚说得清。

## 2. 只改一个变量

| | v1 | v2 |
|---|---|---|
| **参数网格** | fast{5,10,15,20,25,30} × slow{40,60,80,100,120,150} = **36 组** | fast{4,6,…,40} × slow{45,50,…,200} = **608 组** |
| 数据生成器 / 种子 | 零漂移 GBM，seed 1–20 | **一字未动** |
| 样本内外切分 | 0–999 / 1000–1999 | **一字未动** |
| 策略 / 成本 | 双均线 long-flat / 5bp | **一字未动** |
| 判定阈值 R1–R4 | 0.5 / 0.30 / 0.5 / DSR | **一字未动** |

**只有网格变了。** 单变量才能把结果的变化归因到"可搜索空间变大"上。
特别是**判定阈值一个字都没改**——如果连阈值一起动，这一轮就什么也不能证明。

## 3. 预期，以及为什么写下来

预期 F 显著上升（试得越多，纯噪声下的最大值越大），P 与 N 仍贴着 0，
而 `E[max SR]` **同步上升**，R4 仍成立。

> 如果 F 上升而 DSR 也跟着上升、并仍然判得住，那才是本轮真正要展示的东西：
> **一个漂亮的回测夏普会随着你试的次数一起长大，而 Deflated Sharpe 知道你试了多少次。**

若 R4 这次失守（F 超出期望最大值），**必须优先怀疑数据生成器或实现，而不是宣布发现了 alpha**——
真 alpha 已知为 0，任何"发现"在这里都只能是仪器故障。

## 4. 实现上的一处改动，及其边界

`backtest-v2.mjs` 把移动平均从朴素 O(n·w) 改成滑动窗口 O(n)，并按种子缓存各窗口的 MA。
608 组 × 20 种子不这么做跑不完。

**这是实现优化，不是判据改动**，但它必须被验证而不是被声称：v2 跑手在 608 组里**包含 v1 那 36 组**
（fast{5,…} 已不在新网格里——见下），因此不能直接逐值比对。改用另一条：
**v2 跑手同时以 v1 网格跑一遍，结果必须与 `RESULTS.json` 逐位相同**，作为优化未改变语义的证据。
这一条写在跑之前，跑完贴进报告。

## 5. 边界

沿用 v1 §7 全部五条，一条不减（合成随机游走 ≠ 真实市场；数据自造；玩具策略；20 种子只够看数量级；
实现出自同一作者）。**另加一条**：本轮 608 组仍是人为挑的一个网格，
它能说明"挖掘空间变大则挖掘溢价变大"，**不能**给出任何真实策略研究中"试了多少次"的估计。
