# 一次真实载荷压出来的架构问题

> 红楼梦是靶子，不是目的。这份清单记的是**本源计算机自己**在这次实战里暴露的东西。
> 每条都有可复跑的实证，不是设想。

## 为什么这次能压出东西

之前的 demo 任务大多是「跑通一个闭环」——路径短、数据小、一个会话干完。
这次不一样：**87 万字语料、33 条谓词、六道校准判据、两次跨 harness 交接、十二次判分器返工**。
路径一长，协议里那些「理论上有风险」的地方就变成了实际事故。

---

## 一、本境：写入闸门不校验 schema（P0，待 RFC）

**现象**：`benjing-put` 只做乐观锁，不做 schema 校验。schema-check.mjs 完全可用、也确实能抓，
但**写入路径上没人调用它**。不合规的学历能合法入盘，然后在下游以 TypeError 的形式爆出来。

**实证两次，第二次来自另一个 harness**：

| 次序 | 谁写的 | 违规内容 | 后果 |
|---|---|---|---|
| 1 | claude-code | `artifacts` 用了 `[{path,what}]`，schema 要求 `string[]` | `reobserve.mjs` 与 `verify-state.mjs` 双双 ERR_INVALID_ARG_TYPE，本象判据由 14/14 掉到 13/14 |
| 2 | **codex** | `facts[61].source_kind = "path+command"`，不在允许集内 | 全文件唯一一处不合规，当时无人报错 |

```bash
node demo/hongloumeng-c/repro-schema-gate.mjs   # 退出码 0 = 洞仍开
```

**这条比想象中重**：第二次是从**另一个 harness** 写进来的。本会话有 `PreToolUse` 硬拦截护着，
codex 那侧没有。**缺陷的严重性不能只按本 harness 的暴露面估。**

---

## 二、下游把「数据不合规」伪装成「程序 bug」

`benxiang/observe.mjs:33` 与 `southbridge/verify-state.mjs:32` 拿到非字符串路径时直接
`path.isAbsolute()` 抛 `ERR_INVALID_ARG_TYPE`。

看日志像是程序崩了，实际是数据不合规。**这两件事的处置完全不同**：前者该改代码，后者该改数据。
协议层应给出协议级错误，而不是让 Node 的类型错误冒上来。

---

## 三、南桥审计覆盖不全

```bash
node oob/crosscheck.mjs    # 退出码 1，27 处分歧
```

分歧都是「产物由编辑工具直写、未走南桥」。带外对账自己给了良性解释，但它同时意味着：
**这些产物没有经过风险判级、没有备份、审计里查不到是谁写的。**

Claude Code 侧用 Write 工具是常态，于是南桥的审计事实上只覆盖了无头 harness 那一半。

---

## 四、「各部件各写各的」在数据层复发

RFC-0006 §0 记的是「别在部件里各写各的 sha256/existsSync」。这次复发在**数据层**：

分回逻辑（把一部章回体小说切成回）先是写在变点扫描探针里，后来判词抽取也要用。
两个消费者一出现，就必须抽成 `corpus.mjs`——否则两份实现必然漂移。

抽取时还差点漏掉一个字符类（全角空格），那会让韵文识别整体失效。
**行为等价重构必须复现同样的数字**，这次复现了（3.0932 / top5 完全一致）。

---

## 五、恒绿考题的四种新形态

本仓协议里「恒绿考题」原本指**判据永远为真**。这次压出了四种它的变体，
每一种都能让闸门全绿而实际什么都没测到：

1. **复合判据的半截没被测。** order 类谓词在校准窗口内前一条腿就断了，
   后一条腿根本没跑过，却随整条谓词过闸——到了目标窗口才暴露它绑错了人。
   → 加固：`C0.5` 强制复合谓词声明各腿的校准来源。

2. **「不存在」类结论没有召回凭据。** 「未交代」和「我没找到」在账面上分不开。
   首次开启该检查即发现 15 条谓词全无凭据。
   → 加固：`C0.6` 三选一（自证 / 他证 / 显式承认未证）。

3. **出处校验只查共现。** 校验批语出处时，第一版只查「批本名在该回出现过」——
   而庚辰批遍布全回，这道检查恒为真。
   → 加固：改查引文的**紧邻前置标记**。

4. **只测召回不测误报。** 只有正例的闸门是恒绿的：把谓词放到最松，召回必然满分。
   → 加固：`C0.3` 要求正负例都非空；当前校准集负例占多数。

---

## 六、补召回会连锁暴露被掩盖的精度问题

归一表漏了「鳳姐」（出现于 102 回，而全名只出现于 12 回）——凡以王熙鳳为主语的谓词，
实际只覆盖了相关文本的不到一成。

补上之后，同一条谓词**立刻两轮误报**：先是裸「金陵」命中护官符，再是「送靈」命中秦可卿的葬礼。

**教训**：原先不误报，可能只是因为召回不足。补召回与收紧精度必须一起做，
否则会先得到一个「看起来更好」的假象。

而这个缺口是怎么发现的？不是通读别名表，是**给谓词配了召回对照，对照漏报才浮出来**。

---

## 七、学堂：recheck 的判别力仍未证明

```bash
node xuetang/exam.mjs --dry-run
```

考试会诚实报出「N 条考题从未红过，判别力未证明」。本轮新增的经验大多也在此列——
它们的 recheck 挂的是 C0 闸门，而闸门当前是绿的，所以那些 recheck 从未见过红。

这不是缺陷，是**待办**：一条经验要真被验证，它的 recheck 得在经验被违反时确实变红。
目前只能说「跑得通」，不能说「分得开」。

## 一句话

这次实战最值钱的不是红楼梦的任何结论，是**每一次加固都因为先骗过了自己一次**：
伏笔被当成兑现、复合谓词半截没测、未交代没有凭据、归一表静默少召回、
成语被当成死亡、另一个 harness 的坏数据合法入盘。

十二次返工全部留痕。**不留痕的调参与凑答案，在账面上长得一模一样。**
