## 为什么这是个真问题，而不是复核器在挑刺

判据底表的用途是让判分器判「某段文本有没有和前八十回的亲属事实矛盾」。
一条方向未证的记录进了底表，判分器会拿它去判别人——而它自己没被任何东西验证过。
「没被检查过的东西不能当判据」，这是本项目的硬规矩，不是这一轮临时加的。

## 你要做的三件事

### 一、36 条：换一句带属格结构的引文

这些记录的 subject/relation/object **多半是对的**，问题只在 grounding 那句话。

**要求**：grounding 里必须出现 `<subject的原文名字形>之<relation>` 或 `…的<relation>`。

| 记录 | 当前引文（证不了方向） | 该换成这类 |
|---|---|---|
| `K-011 榮國公 -兄- 宁國公` | `當日宁國公與榮國公是一母同胞弟兄兩個` | 含「X之兄」「X之弟」的句子 |
| `K-012 賈代化 -子- 賈敷` | `宁公死後，賈代化襲了官，也養了兩個兒子：長名` | 含「賈代化之子」或「…之長子」的句子 |
| `K-002 林黛玉 -母- 賈氏` | `今只有嫡妻賈氏，生得一女，乳名黛玉，年方五歲` | 含「黛玉之母」的句子 |

原文找得到这类句子的场合比你想的多——第二回冷子兴演说荣国府整段就是世系交代，
「之」字属格密集。**先在原文里找那句，再决定这条记录怎么写**，不要反过来。

关系词可以用同义词，复核器认这些：
妻＝夫人/嫡妻/正室；母＝生母/母親；父＝生父/父親；子＝兒子/長子/次子；
女＝女兒；兄＝哥哥/長兄；姐＝姊；孫＝孫子；侄＝姪。

### 二、找不到就**显式声明**，不要硬凑

原文确实没有属格句子的（比如兄弟关系常写成「一母同胞弟兄兩個」，本来就不分方向），
给该条加两个字段：

```json
"direction_unverifiable": true,
"direction_note": "第二回只写「宁國公與榮國公是一母同胞弟兄兩個」，原文未指明长幼，方向不可由文字判定"
```

声明过的条目**不算错**，会被计数并公开，只是不进底表。
**编一句不存在的引文去凑属格结构，是比声明不可判严重得多的错误。**

## 唯一的读法（沿用 v2，没变）

> **`<subject>` 的 `<relation>` 是 `<object>`**

## 铁律（沿用，违反任一条该条作废）

1. `grounding` 是原文一字不差的**连续**片段，8–40 字。程序逐字回查，并核对它是否真在你声称的那一回。
2. 只抽原文明说的，不推理。
3. 找不到原文支持就不写。**少写不扣分；编造和写反是最严重的错误。**
4. 繁体照抄，不转简体。
5. `grounding` 不含 `{{ }}【 】` 等标记。
6. **（本版收紧）** grounding 里必须至少出现 subject 或 object 之一的名字形；
   且方向要么由属格结构可判，要么显式声明 `direction_unverifiable`。
