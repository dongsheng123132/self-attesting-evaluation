# 给续写者的缺口清单

> 由 `node demo/hongloumeng-c/make-gap-report.mjs` 生成，数字现跑。
> 面向对象是写续编的人，不是我们自己。

## 这份清单是什么，不是什么

**是**：曹雪芹在第五回判词与十二支曲里写下的结局规格、以及脂砚斋批语记载的佚稿线索中，
目前**既没有在后四十回兑现、也没有在已公开的续编（第一二一至一二五回）里出现**的那些条。

**不是**：文学评价。本判分器只判「文本里有没有」，不判写得好不好。
一条没出现在清单里，只说明机器检索到了相应文字，不代表写得对、更不代表写得好。

## 一个必须先说的问题：公布谓词等于公布考题

下面每条都附了「判分器要看到什么才判兑现」——也就是检索谓词。
公布它意味着：照着谓词写，就能让判分器变绿，而判分器对你就失效了。

我们仍然照公布，理由三条：

1. 判据本身来自**公开的**判词与脂批，不是我们发明的考题，藏无可藏；
2. 藏着考题去抓人不是我们的立场——判据可公议，才谈得上可信；
3. 但请记住：**「写来通过谓词」不等于「兑现判词」**。谓词只是判词的一个粗糙代理，
   它认的是字面。真正要兑现的是判词那句话本身，那件事机器判不了。

## 判分器的已知局限（请据此打折）

1. **只认叙述语**。人物口中说的不算——因为红楼梦的伏笔在字面上就等于兑现，
   采信人物话语会把全书伏笔一律判成已兑现。所以借人物之口交代的，机器看不见。
2. **靠主语名邻近绑定**。整段不出现人名时会漏判：实测第一〇九回「可怜一位如花似月之女，
   結褵年餘，不料被孫家揉搓以致身亡」——整句无「迎春」二字，我们最初就判漏了，
   是外部复核指出来的。
3. **跨正字法靠手工映射表**（81 对，见 `t2s-map.json`）。遗漏的表现是漏判而非误报，
   即**偏向低估续编**。若你认为某条明明写了却被判未见，多半是映射或谓词的问题，欢迎指出。
4. **只公开了 5 回**。若其余章回已写，本清单相应条目可能已被兑现，重跑即可更新。

## 怎么反驳我们

```bash
node demo/hongloumeng-c/verify-c0.mjs        # 判分器有没有资格判（不绿则以下全部作废）
node demo/hongloumeng-c/judge-external.mjs   # 对已公开续编的逐条判决与证据
node demo/hongloumeng-c/make-gap-report.mjs  # 重新生成本文件
```

判分器在校准过程中被改过 17 次，每次改了什么、因为撞见了哪句原文，
都记在 `c0-calibration.json` 的 `revision_log` 里——包括让我们自己难堪的那些。
