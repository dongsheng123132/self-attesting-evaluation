# RFC-0008 · 学堂协议 v0.1（xuetang/0.1）

- 状态：Draft，参考实现已通过验证（`node xuetang/verify-xuetang.mjs`，26 条判据其中 17 条反向）
- 依赖：本境 `2origin/0.2`（落盘走乐观锁）、北桥 `northbridge/0.2`（装载）、schema 承重件
- 命名冻结期内不改：学堂 / 经验 / 考试

---

## §0 结构性成因：为什么这条协议是被「一个数字」逼出来的

项目叫「学堂」，主板上却一直没有学堂。`learnings` 这个字段从第一天就在 schema 里，
也被本境的缩水守卫保护着（B11.3b / B12.1）——但**没有任何代码写过或读过它**。

盘点时的实际数字比「空」更难看：

| | 条数 |
|---|---|
| 学历里的经验总数 | **58** |
| 其中自称 `status: "verified"` | **49** |
| 其中带有可被任何人重跑的检验 | **0** |
| 其中被任何代码读取过 | **0** |

49 条经验自称已验证，`confidence` 一律 0.85~0.95，**全部由写下这条经验的同一个
agent 自己填的**，并且没有任何一条可以被推翻。这不是「学堂还没做」，这是
**「作者给自己发证」跑了 58 次**——本仓库反复命名的那个病（「决策权与判断依据分离」
失守）在最没人看的角落里规模化了。

修法不是再写一个「经验管理器」。是找那个缺失的对称：

> 本境要求 **fact 的 `source` 必须引用可复核物**（`recheckSource`）。
> 对称地，**learning 的 `recheck` 必须是可重跑的动作**。
>
> 没有可重跑的检验，这条经验永远无法被推翻，也就永远不该叫 verified。

## §1 五条规则

| # | 规则 | 对应的实测教训 |
|---|---|---|
| **R1** | 没有可重跑检验的经验，最高只能 `candidate` | 「未验证的话不配叫 fact，叫假设」——经验比事实更容易自我感动 |
| **R2** | 升级只能由考试给，作者不能自己写 `verified` | 「把决策权放在没有判断依据的层上，防护必然漏」 |
| **R3** | 一次成功不是永久真理：每次考试都重跑，跑挂当场降级 | CLAUDE.md 铁律原文 |
| **R4** | 考试必须逐条记账（pass/fail/error/unexaminable），降级要说明是哪次考试降的 | 「不报告丢弃量等于谎报覆盖率」 |
| **R5** | 只有 `verified` 进上下文，`candidate` 不进 | 让未验证的经验进上下文 = 把假设当经验用，比不写更糟 |

### R3 的三态，不是两态

`error`（命令跑不起来、超时）**既不升也不降**，只计入 `errors`。
把 error 当 fail，会让「环境坏了」冒充「经验错了」——那是一个新的自证来源。
这条有反向判据 X3.3 锁死。

## §2 数据模型

```jsonc
{
  "id": "L-1ffaf4b2fae7",          // learningId(lesson)，跨学历同一条经验同一个 id
  "lesson": "凡是缓存过去结论的地方，命中时都必须回头看世界一眼",
  "status": "verified",            // candidate | verified | deprecated
  "confidence": 0.9,
  "origin": { "task": "task3", "when": "..." },
  "recheck": {                     // ← 这条经验被违反时，什么东西会变红
    "kind": "command",
    "run": "node southbridge/verify-southbridge.mjs",
    "expect_exit": 0
  },
  "exam": {                        // ← 只由 xuetang/exam.mjs 写
    "runs": 3, "passes": 3, "fails": 0, "errors": 0,
    "last_run": "...", "last_result": "pass", "promoted_at": "..."
  }
}
```

schema 里用 `if/then` 把 R1+R2 变成承重约束：`status === "verified"` ⇒ `required: [recheck, exam]`。
判据 X4.1 反向锁死；X4.2 确认 `candidate` 不被误伤（经验可以先记下来，只是不许自称已验证）。

## §3 考试怎么跑

```bash
node xuetang/exam.mjs             # 跑一轮并写回
node xuetang/exam.mjs --dry-run   # 只跑不写
node xuetang/exam.mjs --json      # 机器可读
```
退出码：`0` 全通过（或无经验）　`1` 有降级/失败/不可考　`2` 写回失败。

三条它自己必须守住的规矩，都有判据：

- **X6.1** 考试器源码里不得出现 `writeFileSync`——学堂自己开写路径就是 task5 那次学历被吃掉的复刻；落盘一律 `putState(..., {expect: contentHash(...)})`。
- **X6.3** expect 过期必须 `diverged` 且磁盘不变（真跑一次，不读源码）。
- **X6.4** 0 条经验必须报成「这不是通过，是空」——不能因为循环没进去就默认打全绿（bundle 谎报装载量的同型）。

### 考题的执行边界

`recheck.run` 不走 shell：管道、重定向、`&&`、换行一律拒绝（X1.3）。
首词白名单是本境 `recheckSource` 命令词的**子集**（X7.3），差集必须在
`EXECUTION_DENIED` 里写明理由（X7.4）并确实被拦住（X7.5）。

两边为什么不相同——这是 v0.1 当场被自己的判据纠正的一处：
**本境只是「认出」一句话里提到了命令（从不执行），学堂是「反复自动执行」。**
所以 `rm` / `touch` 本境认、学堂拒（考题只许观察，不许改变被观察的东西）；
`bash` 学堂也拒，因为 `bash x.sh` 会把「跑命令不跑脚本」的保证从后门绕过去。

## §4 首轮实测

```
第一轮：58 条经验 → 58 条「不可考」，49 条 verified 当场降级为 candidate
挂上 6 条 recheck（只挂能辩护的：违反这条经验时那个验证器会变红）
第二轮：通过 4　挂了 2　—— 两条挂的都指向 verify-benjing.mjs
第三轮：通过 6　挂了 0　52 条仍为 candidate
```

第二轮那两条挂得有价值：**是本轮 schema 改动打破了 `verify-benjing` 自己的判据夹具**
（B12.1 的 fixture 写了 `status:"verified"` 却没有 recheck/exam，B12.6 随之判「合规状态被误报」）。
学堂上线第一天就用一条经验的 recheck 把一次回归失败揪了出来——这正是长循环考试存在的理由。
修法遵循本仓库既有结论：**新检查器抓到旧数据，默认改数据不改检查器**，所以改的是夹具。

**52 条仍是 candidate，这是结论不是遗留**：大部分经验没有机器可跑的检验。
协议让这件事**可见**，而不是让它们继续挂着 `verified: 0.9`。

## §5 装载（R5）

北桥 `compileRequest` 增加独立的经验段：独立预算（默认 900 字符 / 至多 4 条），
不与事实抢——被事实挤掉的经验等于没沉淀。

与事实的一处**故意不同**：经验**不排除当前任务**。事实是「这个任务发生过什么」，
boot 已给全；经验是「下次别再这样」，它天然跨任务。

判据 X5.1（反向）锁死 candidate 不得注入，X5.2 确认 verified 会被调入并标明它靠哪条命令过的考试。

## §6 未决

1. **`deprecated` 没有入口。** 现在只有 candidate ⇄ verified 两态在动。一条经验被新事实推翻时应由谁标记 deprecated，未定。
2. **52 条不可考的经验没有出路。** 需要一种比「跑命令」更弱、但仍非自述的检验（例如「引用一条 verified fact 的 id」），否则它们会永远沉在 candidate。
3. **考试没有定时器。** 现在必须手动跑。接 cron 之后才叫「长循环」，现在只是「可重跑」。
4. **经验去重只在读取侧（`collect`）做。** 写入侧允许同一条经验落在多份学历里，跨学历重复会随任务数增长。
5. **`recheck` 与经验的语义绑定靠人判断。** 「违反这条经验时这个验证器会变红」没有机制保证；
   挂一个恒绿的命令（`node --version`）就能骗过考试，而账面上它跟真考题长得一模一样。
   **这是本协议最大的洞，v0.1 不假装解决它，但把它变成了可测量、可报告的数：**

   一条考题只有在**被观察到红过至少一次**之后，才算证明了自己分得开好坏
   （`discriminating(l)`，判据取自考试账本 `exam.fails > 0`，不取任何自称字段）。
   考试每轮都要把「判别力未证明」的条数单独打出来——**不报这个数，
   「6 条经验通过考试」就会被读成「6 条经验被证明为真」**，而其中可能有恒绿考题。
   这与判分器必须单独统计 `finish_reason=length` 是同一条规矩：不报告未证明量 = 谎报证明强度。

   首轮实测：**6 条考题里只有 2 条曾被观察到红过**（那两条恰好是本轮 schema 改动
   打破 `verify-benjing` 夹具时红的），其余 4 条判别力未证明。这个 2/6 是当前
   「学堂已验证 6 条经验」这句话的真实成色。

   刻意**不**做的两件事：不因「未证明」拒绝升 verified（第一天就会卡死 4/6，
   而且"从没红过"不等于"是假考题"）；不做变异测试去主动证明判别力（代价与收益不成比例）。
   让它显形，比让它消失更诚实。

6. **git 与学历的写路径冲突（2026-08-09 新增）。** 这台机器纳入版本控制后，
   `git checkout` / `stash` / `reset --hard` 会用提交里的版本覆盖工作区的 `task.origin.json`——
   **绕过本境乐观锁（它只管 `putState`），也绕过 PreToolUse 守卫（它只管 Write/Edit 工具）**。
   并发会话刚写入的已验证事实会静默消失。缓解在 `hooks/branch-safety.mjs`
   （`precheck` 切前拦、`post-checkout` 切后如实报告），但那是约定不是强制点——
   **和乐观锁一样，是协作机制不是权限机制。**
