# RFC-0006 · 本象协议 v0.1（Benxiang State Protocol）

**Spec ID:** `benxiang/0.1`
**Status:** Draft — 参考实现已通过验证（`node benxiang/verify-benxiang.mjs`，14/14，连跑两轮一致）
**原则:** 观察者不接收预期。「看」和「判」必须是两步；合在一起就是自证。

---

## 0. 为什么现在才装它

不是因为路线图排到这里，是因为**复盘后发现它是主板上唯一没装的部件，而所有反复出血的地方都指向它**。

用哲学透镜（`philosophy-existence-vs-verification`：①系统把「声明」当成「事实」 ②决策权与判断依据分离）审视本仓库全部已修缺陷，得到三条根因。

### 根因一 ·「自证」复发五次，因为专职观察者没装

| 次序 | 现场 | 形态 |
|---|---|---|
| 1 | 影核 `action.result` | `writeFileSync` 没抛错就报 `done` |
| 2 | 影核幂等账本 | 账本记得 `done` 就返回 `replayed`，不看世界（补 `diverged`） |
| 3 | 本境 `version` | 每次 SessionEnd +1，与内容无关 |
| 4 | 本境 bundle 预算 | 统计者把自己（header/footer）排除在统计之外 |
| 5 | 本境体检 | 只清点它认得出的学历，`kind` 坏掉的直接消失且照报「全部健康」 |

五次都被当作独立 bug 修掉了。但结构性原因是同一个：

> **主板七个部件装了六个。唯一没装的本象，恰恰是那个专职「回头看世界」的部件。**
> 于是「看世界」被摊派给每个部件自己实现，每个部件都要独立重新发明「怎样才算真的看见」，每次都漏一点。

实测佐证（全部取自磁盘）：

- `createHash('sha256')` 在 `shadowcore-core.mjs`(3 处)、`benjing-core.mjs`、`verify-southbridge.mjs` 里各写一遍
- 影核的 `southbridge_verify` 与写动作同进程 —— RFC-0004 §6.5 自己就承认「严格说不算独立观察者」
- 本境的 `health()` 是本境自己看自己
- `southbridge/audit.log` 里 **772 条带 evidence 的声明，今天仍与世界一致的只有 8 条**，而在本 RFC 之前，**没有任何机制会告诉你**

而 `verify-state.mjs` / `verify-benjing.mjs` / `verify-southbridge.mjs` 其实就是本象散落的三块碎片——独立进程、只信磁盘真相。我们已经无意中造了三次，只是没认出它们是同一个零件。

### 根因二 · 闸门必然是半道门，因为决策权放在了没有判断依据的层

| 闸门 | 决策权 | 判断依据只有 | 必然后果 |
|---|---|---|---|
| codex 沙箱 | 有 | 路径 | 一刀切（影核 v0.1 缺陷④） |
| 文件系统只读位 | 有 | 文件 mode | **分不清 `benjing-put` 和 `sed`** |
| `PreToolUse` hook | 有（仅 Claude Code） | 工具名 + 路径 | 覆盖不到 codex |
| 影核 risk 分级 | — | 判断依据最全 | 对不经过它的写**没有决策权** |

所以「只读位挡不住删了重建」不是实现不够好——**是它所在的层根本看不见「这次写有没有出示 expect」**。往没有判断依据的层加闸门，加多少道都漏。正解是让有判断依据的那层成为唯一必经之路。

### 根因三 · 北桥插错了插槽

bundle 的相关性筛选一直做不对，之前归因为「还没有实测失败」。真实原因更硬：**北桥装在 SessionStart，而那一刻还没有 goal。** 它的职责是「CPU 此刻需要知道世界的哪一部分」，却被放在「此刻还不知道要干什么」的时刻——在这个位置上相关性筛选**原理上就做不对**，轮转公平分配已是天花板。

架构文档的 `context.request` 正是解这个的（假设 Harness 拿到 goal 之后才要 context）。此前以「只有一个消费者」为由拒绝它，那个理由是错的：**不是消费者少，是消费者被放在了错误的时刻。**

### 结论：主板设计没问题，装机有问题

架构文档 §9 那句被一笔带过的话——

> 「工具返回 success 不等于任务已经成功，系统应通过本象重新观察现实状态进行验证」

——正好指着我们出血最多的地方。**装了六个部件、漏了一个、还有一个插错插槽。**

## 1. 本象只回答一个问题

**世界此刻是什么样。**

不回答「对不对」「该不该」「符不符合预期」。那些是上层的事。

```json
{
  "spec": "benxiang/0.1",
  "kind": "state.object",
  "id": "2o:file:demo/task1/task.origin.json",
  "type": "file",
  "observed_at": "2026-08-08T10:51:59.237Z",
  "observer": { "pid": 51716, "cwd": "…" },
  "properties": {
    "exists": true, "size_bytes": 4021, "sha256": "…",
    "mtime": "…", "writable": false, "json_kind": "task.origin", "json_spec": "2origin/0.2"
  },
  "projections": ["bytes", "json"],
  "relations": []
}
```

## 2. 独立性铁律：写在接口上，不是写在注释里

```js
observe(target, root)          // 只接受「看哪里」
observe(target, root, expected) // ← 直接抛错
```

一旦允许传入预期，观察器就退化成确认偏误机——**那正是它要治的病**。比对是调用方的事，且必须发生在拿到观察结果之后（`compare(stateObject, claimed)`）。

判据 X1.1（拒收预期）、X1.2（`state.object` 里不许出现 `ok/pass/verdict/valid` 任何判断字段）、X1.3（看与判分两步）锁住这条。

三条继承自具体出血的判据：X2.1「不存在」是合法观察结果而非异常（影核 v0.1 在这里出过血）、X3.1 `size_bytes` 是 UTF-8 字节数不是 JS 字符数（影核 v0.1 在这里证错过）、X4.2 按 `kind` 认对象而不是按文件名（本境缺陷⑥）。

## 3. 「回头看」：只看一眼不算观察

影核 v0.2 修的是**「声明当场就是假的」**（写完立刻回读）。
它没修的是**「声明当场为真，之后世界变了而没人知道」**——那是两个病。

`benxiang/reobserve.mjs` 每轮做三件事，并把结果**追加**到 `benxiang/observations.jsonl`：

1. **学历自身**：JSON 是否可解析、`kind` 对不对、只读闸门还在不在
2. **活的声明**：学历 `artifacts[]` 声称的产物现在还在不在；**并与上一轮的观察比对**（内容变了 / 失效了 / 新增了）
3. **历史声明**：影核 `audit.log` 的 evidence 与今天的世界差多远（只报统计，不报警——历史记的是「当时」，那没错）

账本的意义：**「上次被独立观察是什么时候」这个问题，在本仓库以前没有任何地方能回答。**

判据 X6.1（账本只追加不覆盖）、X6.2（每轮记 `observed_at`）、X6.3（第二轮起必须产出 `compared_with` 与 `delta`，否则它还是「看一眼」而不是「回头看」）。

## 4. 一处观察，多处引用

本境的 `health()` 已改为走 `observe()`——顺带把原来那句 `existsSync` 换掉了，**那本身就是一次「存在性检查冒充验证」**。判据 X7.1 直接检查 `benjing-core.mjs` 是否引用了本象，防止「看世界」重新散落回各部件。

影核暂未接入：它正被另一个会话改动，避免冲突。接入前先用本象对 `audit.log` 做**回溯审计**（§3 第 3 项），拿到实测差距再谈改动。

## 5. 刻意没做的事

- **把本象做成常驻服务 / 独立进程守护**：当前观察是同进程函数调用。严格说这仍不是「另一个进程在看」，但它至少**不接受预期、不含判断、被三个协议共用**。等出现「调用方能影响观察结果」的实测案例再升级。
- **非文件对象（GUI / 浏览器 / Office / 设备）**：架构文档里本象要覆盖这些。本仓库现在只有文件这一种世界，造别的是过早抽象——同 RFC-0004 §5 对「一核多影」的判断。
- **state.diff**：`compare()` 已够用。真正的 diff 要等有第二种对象类型。

## 6. 未决问题

1. **本象仍是同进程调用**，不是独立观察进程。影核 RFC-0004 §6.5 提的那个问题在本象这里同样存在，只是被「接口拒收预期」削弱了。
2. **影核尚未接入**，`sha256` 仍在 `shadowcore-core.mjs` 里自己实现 3 处。
3. **学历不记录 artifact 指纹**，所以「产物内容变没变」只能靠账本跨轮比对，第一轮无从判断。
4. **`reobserve` 尚未自动化**（未接 cron / SessionEnd）。一个不被定期运行的「回头看」，等于没有回头看——这正是本 RFC 要治的病，别让它在自己身上复发。
5. **根因二、三尚未修**：Trust 的统一落点、北桥挪到有 goal 的时刻（`context.request`）。这两条要动影核与 Harness 接口，是下两个 RFC 的事。

```bash
node benxiang/verify-benxiang.mjs   # 14/14

```
